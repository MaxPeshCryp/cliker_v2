# Кликер

## Локальный запуск

Нужен Python 3.11+.

```powershell
py -3 -m venv C:\\Users\\$env:USERNAME\\clicker-venv
C:\\Users\\$env:USERNAME\\clicker-venv\\Scripts\\python.exe -m pip install -r requirements.txt
$env:CLICKER_SECRET_KEY = "вставьте-длинную-случайную-строку"
C:\\Users\\$env:USERNAME\\clicker-venv\\Scripts\\python.exe app.py
```

Откройте `http://127.0.0.1:5050`.

## Установка на телефон (PWA)

Кликер устанавливается с кнопки «Установить» в шапке. В Chrome/Edge на Android
появится системное подтверждение установки, когда браузер сочтёт приложение
готовым. Если приглашение пока недоступно, кнопка показывает инструкцию для меню
браузера. На iPhone/iPad: Safari → «Поделиться» → «На экран Домой» → «Добавить»;
если есть переключатель «Открывать как веб-приложение», включите его.
После установки запускайте игру с новой иконки.

Манифест запрашивает `fullscreen`: на поддерживаемых устройствах игра занимает
весь экран. Если браузер не поддерживает этот режим, применяется его стандартный
переход к `standalone` (без адресной строки). На iOS системная строка состояния
может оставаться видимой. В обычной вкладке есть отдельная кнопка «На весь экран»,
если браузер поддерживает Fullscreen API. Вёрстка учитывает вырез камеры и нижнюю
область жестов; масштабирование страницы остаётся доступным.

Виброотклик включён по умолчанию, если браузер поддерживает `navigator.vibrate`:
12 мс на основной клик и клик мини-игры, 8 мс на остальные кнопки. Кнопка
«Вибрация» отключает его и сохраняет выбор на устройстве. На iPhone/iPad
веб-приложения не поддерживают этот API; установка PWA не снимает ограничение.
Фактический отклик также зависит от оборудования и настроек устройства.

На телефоне для установки и service worker нужен **HTTPS**; локально подходит
`http://localhost` или `http://127.0.0.1`. Обычный HTTP-адрес компьютера в локальной
сети для установки не подходит. Используйте настроенный HTTPS-домен проекта.

Игра остаётся сетевой: баланс, покупки, забеги и рейтинги проверяет сервер.
Service worker хранит только экран отсутствия связи и иконки, без API-ответов,
данных аккаунта и админ-панели. При запуске без сети показывается кнопка повтора;
при возвращении подключения игра открывается автоматически. Уже открытая игра
показывает уведомление об отсутствии интернета. Новая версия service worker
применяется кнопкой «Обновить» или после закрытия всех окон игры; активная партия
не перезагружается автоматически. При изменении `offline.html` или иконок увеличьте
версию `CACHE_NAME` в `service-worker.js`.

## Быстрый вход: биометрия и PIN

После входа по почте и паролю нажмите **«Быстрый вход»** рядом с профилем.
Введите пароль аккаунта для подтверждения, затем подключите биометрию или
задайте PIN ровно из шести цифр и повторите его. Можно включить оба способа.
Настройка действует на этом браузере 90 дней. После обычного выхода из аккаунта
на странице входа появятся кнопки биометрии и PIN; почта больше не нужна.
Обычный вход по паролю остаётся доступен. Существующий вход в аккаунт продолжает
действовать без дополнительной блокировки при каждом открытии приложения.

Биометрия использует WebAuthn и системный ключ доступа: Face ID, отпечаток,
Windows Hello или системный код устройства. Конкретный способ проверки
выбирает ОС; сайт не получает биометрические данные. Если на устройстве нет
подходящего системного аутентификатора, используйте шестизначный PIN. Его
придумывают в игре отдельно от кода разблокировки телефона.

Для включения любого способа нужен текущий пароль. PIN проверяет сервер:
он хранит только медленный хеш, связанный со случайным секретом устройства
из HttpOnly cookie. Пароль и PIN не сохраняются в `localStorage`. После пяти
неверных PIN вход по нему отключается; для восстановления войдите паролем
или биометрией и заново настройте PIN, подтвердив пароль. Счётчик сохраняется
на сервере между перезапусками и не сбрасывается обновлением страницы.
Подтверждение пароля ограничено пятью неверными попытками за пять минут.

WebAuthn проверяется библиотекой `webauthn`: одноразовый запрос истекает через
две минуты, сервер проверяет домен, origin, подпись и обязательную проверку
пользователя. Бан, разбан и административный сброс отзывают все прежние
устройства через версию сессии. Кнопка **«Отключить быстрый вход на этом
устройстве»** отзывает оба способа для текущего браузера. Обычный выход
сохраняет настройку быстрого входа. Браузер и установленное PWA могут хранить
cookie отдельно, поэтому внутри PWA настройте вход после установки.

Перед запуском обновлённого сервера установите `requirements.txt` (добавлена
библиотека `webauthn`). Для телефона нужен HTTPS. Для локальной проверки
биометрии используйте `http://localhost:5050`. По умолчанию разрешены два
HTTPS-домена проекта; другой адрес задаётся в `CLICKER_AUTH_ORIGINS` как точный
origin, например `https://game.example.com`, без пути, несколько — через запятую.
Это работает и за существующим Nginx без доверия произвольному `X-Forwarded-Host`.

## Админ-панель

Отдельная страница входа — `/admin/login`, панель — `/admin`.
Игровой аккаунт не даёт административных прав. Без настроенных хешей вход
администратора отключён. Данные игроков и действия доступны только после входа.

На VPS создайте или обновите данные входа интерактивно:

```bash
sudo /var/www/clicker/venv/bin/python /var/www/clicker/app/admin_credentials.py --env /var/www/clicker/.env
sudo systemctl restart clicker
```

Команда запрашивает логин и пароль скрытым вводом. Пароль — не менее 12 символов.
В `.env` записываются только солёные scrypt-хеши `CLICKER_ADMIN_LOGIN_HASH`
и `CLICKER_ADMIN_PASSWORD_HASH`; другие настройки сохраняются. Это одностороннее
хеширование: восстановить исходные данные из файла нельзя. Файл получает права
`600` на Linux; systemd читает его перед запуском сервиса. Логин и пароль не
попадают в аргументы команды, историю shell или Git. Чтобы заменить пароль,
повторите команду и перезапустите сервис; прежние админ-сессии станут недействительны.

Локально выполните `python admin_credentials.py` и перезапустите приложение:
оно читает `.env` рядом с `app.py`. Путь можно изменить переменной `CLICKER_ENV_FILE`.
Переменные окружения имеют приоритет. При обновлении установите зависимости
из `requirements.txt`, включая `python-dotenv`.

В панели есть поиск по нику, email или ID и постраничный список игроков:

- Бан/разбан: запрещает вход и игровые запросы, исключает игрока из обоих видов
  рейтингов и останавливает призовой доход на время бана. После разбана нужен новый вход.
- Добавление/списание точного целого количества кликов: изменяет текущий баланс,
  сохраняя общий заработок и уровень; списать больше баланса нельзя.
- Временный множитель дохода роботов ×2–×1000 на срок от секунды до 365 дней
  с отдельной кнопкой отключения. Без купленных роботов доход остаётся нулевым.
  Бонус сочетается с игровым турборежимом; срок отсчитывается на сервере.
- Выдача/отзыв галочки и 12 административных бейджей (галочка входит в эти 12).
  Можно выдать несколько одному игроку. Награды видны в профиле и рейтингах.
  Они декоративные и существуют отдельно от автоматических наград за уровни.
  Снятая вручную галочка не возвращается из `verified_users.txt` при перезапуске.
- Обнуление с подтверждением ID: очищает баланс, улучшения, роботов, исследования,
  престиж, опыт, оформление, инвестиции, достижения, бейджи, рекламные награды,
  забеги и рекорды; завершает игровые сессии. Ник, email, пароль и статус бана сохраняются.

Админ-сессия действует один час. Изменяющие запросы защищены CSRF-токеном;
после 8 неверных входов действует ограничение до окончания пятиминутного окна,
общее для процессов сервера. Действия записываются в таблицу `admin_audit`.
В production используйте HTTPS и существующую настройку `CLICKER_COOKIE_SECURE=true`.

## Проверенные пользователи

Администратор добавляет email в `verified_users.txt`: один адрес на строку,
без кавычек и запятых. Первым добавлен `kk@kk`. Пустые строки и комментарии
с `#` пропускаются; регистр букв и пробелы по краям не важны.

Список применяется к существующим аккаунтам при запуске сервера. При регистрации
аккаунт из списка также получает галочку. Для выдачи без перезапуска выполните:

```powershell
python verified_users.py
```

Программа использует `CLICKER_DATABASE_PATH`, а если переменная не задана —
`clicker.db` рядом с программой. Для продакшена укажите базу явно:

```bash
sudo -u clicker /var/www/clicker/venv/bin/python /var/www/clicker/app/verified_users.py --database /var/www/clicker/data/clicker.db
```

При обновлении через `deploy/update-vps.sh` сервис перезапускается и автоматически
применяет список из новой версии. Можно хранить список вне Git: задайте
`CLICKER_VERIFIED_USERS_FILE` в окружении сервера или передайте программе `--list /путь/к/списку.txt`.

Программа сообщает, кому выдала галочку, у кого она уже была и какие адреса пока
не зарегистрированы. Повторный запуск безопасен: баланс, пароль и прогресс
не меняются. Удаление адреса из списка не снимает уже выданную галочку.
При ошибке пути программа не создаёт новую пустую базу. Список не доступен
через сайт; другим игрокам передаётся только статус верификации, без email.

## Уровни аккаунта и бейджи

«Путь создателя» показывает уровень, шкалу прогресса и коллекцию наград.
Опыт равен серверному показателю «Всего заработано», а не текущему балансу:
покупки и престиж его не уменьшают. Учитываются все существующие начисления
в этот показатель, включая клики, роботов, доход за места, рекламные награды
и выплаты инвестиций. Монеты отдельного забега не считаются опытом сами по себе.
Существующий заработок игроков учитывается сразу при обновлении.

Уровень 1 начинается с нуля, для уровня 2 нужно 100 монет. Цена каждого
следующего шага растёт на 40% с округлением вверх. Потолка уровней нет.
Бейджи автоматически открываются на уровнях 10 («Искра»), 25 («Механик»),
50 («Инженер»), 75 («Магнат»), 100 («Технолорд»), 150 («Архитектор звёзд»)
и 200 («Легенда кликов»). Они не расходуют монеты и не дают множителей дохода.
Уровень и самый высокий бейдж видны другим игрокам в основном рейтинге
и рейтингах мини-игр. Старые награды остаются в коллекции.

Вдохновение: постоянный уровень аккаунта и отдельные награды за прогресс
в [официальном обзоре Standoff 2](https://help.standoff2.com/en/articles/8759491-2023-recall).
Пороги, названия, оформление и привязка к валюте разработаны для кликера;
ежегодного сброса и отдельного сезонного опыта здесь нет.

## Оформление и аватарки

Кнопка «Оформление» рядом с профилем открывает выбор темы и конструктор аватарки.
Темы покупаются за игровые монеты прямо в окне оформления или в разделе
«Косметика»: «Океан» — 100K, «Сакура» — 250K, «Лес» — 500K,
«Закат» — 1M, «Космос» — 2.5M. Золотая, неоновая и королевская темы
стоят 5M, 50M и 500M. Покупка разовая, переключение купленных тем бесплатно.
Классическая тема бесплатна. Ранее купленные темы остаются открытыми.

Нажмите на аватарку рядом с ником, чтобы выбрать персонажа (робот, кот, медведь,
пришелец), фон, цвет, выражение лица и аксессуар. Предпросмотр обновляется сразу;
кнопка «Сохранить аватарку» применяет образ к профилю и обоим видам рейтингов.
Есть случайный образ и отмена несохранённых изменений. Оформление хранится
в аккаунте на сервере и восстанавливается после входа с другого устройства.
При запуске сервер автоматически добавляет поле аватарки в существующую базу.

Вместо персонажа можно загрузить свою картинку (JPG, PNG, WebP до 5 МБ
и 20 мегапикселей). Она обрезается по центру, а предпросмотр показывается до
сохранения. Сервер проверяет содержимое, приводит изображение к PNG 256×256,
удаляет метаданные и хранит его в базе вместе с профилем. Фотография видна
в обычном рейтинге и мини-играх. «Собрать персонажа» позволяет заменить её
аватаркой из конструктора; изменение применяется кнопкой сохранения.

## Мини-игры на время

Доступны режимы «Спринт» (1 минута), «Тактика» (3 минуты), «Марафон» (5 минут).
На странице показаны компактные карточки. Кнопка «Играть» открывает забег в модальном
окне, «Рейтинг» — результаты выбранного режима. Окно можно закрыть крестиком,
клавишей Escape или нажатием на фон и снова открыть кнопкой «Вернуться».
Таймер при закрытии продолжает идти. При обновлении данных интерфейс меняет только
значения: карточки и кнопки сохраняются, рейтинг и история обновляются при изменении данных.
В каждой попытке отдельный нулевой баланс, клик +1 и нет роботов или бонусов основной игры.
Можно усиливать клик, покупать роботов и ускорять их доход. Результат — остаток монет
на счёте в момент финиша: покупки уменьшают результат. Перед игрой идёт отсчёт 3–2–1,
после которого доступны полные 1, 3 или 5 минут. До старта сервер запрещает клики
и покупки. Автодоход роботов сопровождается анимацией «+N» над счётом. Время, покупки и заработок
проверяет сервер; лимит — 10 кликов в секунду. Одновременно доступна одна попытка,
после финиша можно играть снова без ограничений. Закрытие или обновление страницы
не останавливает таймер. После возвращения показывается сохранённый результат.

У каждого режима свой рейтинг по лучшей завершённой попытке каждого игрока.
Он виден в игровом окне сразу: топ-3, затем место игрока и по одному соседу выше и ниже.
При равном результате выше рекорд, установленный раньше (при одновременном финише —
раньше начатая попытка). Все попытки хранятся в базе, последние 10 видны в интерфейсе.

Автодоход на основной баланс начисляется за время нахождения в тройке, включая время
вне сайта. Для всех трёх режимов ставки зависят от текущего основного баланса:

| Место | Доля баланса в секунду | Минимум в секунду |
| --- | ---: | ---: |
| 1-е | 0,01% | 1 000 |
| 2-е | 0,0075% | 1 000 |
| 3-е | 0,005% | 1 000 |

Например, при балансе 100M первое место даёт 10 000 монет/сек. Сумма округляется
вниз до целых монет. Ставки пересчитываются при обновлении баланса; за время вне
игры начисляется последняя сохранённая ставка, без сложных процентов. При переходе
на новую экономику накопленный доход сначала начисляется по старым ставкам.

Доход разных рейтингов суммируется, при потере призового места начисление прекращается.
Фактические начисления отмечаются отдельной золотой анимацией «🏆 +сумма · за рейтинг»
у основного баланса, а при открытой мини-игре — в её окне с подписью «основной баланс».
Анимация использует точный накопительный счётчик начисленных наград, поэтому не
повторяется при повторном ответе сервера и не смешивается с доходом роботов.
При входе старые начисления принимаются за начальную точку, без повторного показа.
Значения задаются в `timed_games.py`, `REWARD_WEIGHTS` и `MIN_REWARD`. Мини-игровые монеты не переводятся
на основной баланс. Призовой доход не даёт преимуществ в новых забегах.
При следующем API-запросе сервер завершает просроченные игры по времени их финиша
и рассчитывает смены ставок за прошедшее время; фоновый процесс не требуется.
Таблицы создаются автоматически при запуске, существующий прогресс сохраняется.
Старые рекорды один раз пересчитываются по сохранённым остаткам на счёте; история
попыток и уже начисленные награды сохраняются.

## Рекламные бонусы

Реклама открывается только по желанию игрока, по кнопке «Смотреть рекламу»:

- Под балансом: монеты раз в 5 минут. Награда — максимум из 100 монет,
  30 текущих кликов и 60 секунд текущего чистого дохода роботов.
- После мини-игры: однократно за последнюю завершённую попытку можно получить
  сумму её результата на основной баланс. Результат, рекорд и мини-игровой рейтинг
  не меняются. При нулевом результате бонус недоступен.
- Во вкладке «Бусты»: ×2 доход роботов на 60 секунд раз в 10 минут.
  Если турборежим уже работает, его срок продлевается на минуту.

Во всех трёх блоках размещены описание ITeacher и ссылка на https://it.iteacher-alex.org/.
Добавлена иллюстрация для подростков: создание игрового мира на ноутбуке.
Картинка также ведёт на сайт. Файл: `assets/iteacher-young-creators.png`;
описание генерации и исходный промпт: `assets/README.md`.
В рекламном окне — рассказ об индивидуальных занятиях для детей с Алексеем,
уроках по 45 минут и 90% практики. Ссылки открываются в новой вкладке;
переход на сайт не обязателен для получения игрового бонуса. Через 5 секунд доступна кнопка
«Забрать бонус». Закрытие крестиком или Escape без получения ничего не начисляет.
Во время активного забега начать просмотр нельзя. Сервер фиксирует сумму при
открытии, проверяет время, владельца просмотра и защищает от повторного начисления,
в том числе после потери ответа или обновления страницы. Получить бонус можно
в течение 5 минут после открытия. Ограничения хранятся в базе.

Это встроенный рекламный баннер без подключения рекламной сети. Проверка времени сама по себе
не подтверждает просмотр настоящей рекламы; при подключении провайдера в
`rewarded_ads.py` нужна проверка его подтверждения просмотра на сервере.

Дополнительные возможные места: удвоение награды за возвращение в игру,
бонус при нехватке монет на улучшение, необязательный баннер под рейтингом.

## Инвестиции

Сумма вводится числом или с обозначением: `250M`, `2.5B`, `1,25 Qi`.
Поддерживаются K, M, B, T, Qa, Qi, Sx, Sp, Oc, No и Dc без учёта регистра.
Кнопка «Всё» подставляет точный баланс без округления отображаемого сокращения.
Более рискованные вклады завершаются быстрее:

| Вид | Шанс успеха | Прибыль при успехе | Возврат при успехе | Срок |
| --- | ---: | ---: | ---: | ---: |
| Гарантированная | 100% | +20% | 120% вклада | 30 сек. |
| Сбалансированная | 80% | +50% | 150% вклада | 25 сек. |
| Рост | 60% | +100% | 200% вклада | 20 сек. |
| Венчурная | 40% | +200% | 300% вклада | 10 сек. |
| Джекпот | 20% | +500% | 600% вклада | 5 сек. |

При неудаче вклад полностью теряется. Прибыль округляется вниз до целой монеты.
Шанс, сумма возврата и срок фиксируются при создании вклада; получить выплату можно один раз.
Уже открытые вклады сохраняют исходный срок. Срок контролирует сервер.
Старые рискованные вклады сохраняют шанс 50% и возврат x2.

Для разработчика: `amounts.py` разбирает сумму через Decimal и выполняет целочисленные
расчёты. Значения вне диапазона SQLite INTEGER хранятся десятичными байтами (BLOB),
чтобы SQLite не преобразовывал их в неточный REAL. Функция `amount_add` сохраняет
точность списаний и начислений, рейтинг сравнивает целые числа в Python. Старые
числовые записи продолжают читаться. Поле API `userCountExact` содержит точный баланс
строкой; ввод суммы и денежные поля вкладов также передаются строками.

## Проверки

```powershell
C:\\Users\\$env:USERNAME\\clicker-venv\\Scripts\\python.exe -m unittest discover -s tests -v
```

Тесты используют временную базу и не изменяют рабочую `clicker.db`.

Для проверки интерфейса нужен Node.js, Playwright и Microsoft Edge. Запустите
`node tests/test_ui.cjs`, `node tests/test_timed_ui.cjs`, `node tests/test_appearance_ui.cjs`,
`node tests/test_admin_ui.cjs`, `node tests/test_pwa_ui.cjs` и `node tests/test_quick_auth_ui.cjs`. При необходимости задайте
`PLAYWRIGHT_MODULE` (путь к установленному модулю Playwright) и `PYTHON_EXE` (Python

и ускоренными часами, затем закрывает его. Она проверяет все три режима, покупки,
финиш, повторную игру, обновление страницы и мобильную ширину.

## Выгрузка на VPS

Production-конфигурация рассчитана на Ubuntu и домен `max-click-pesh.iteacher-alex.org`.
На сервере создаётся один изолированный каталог `/var/www/clicker`:

- `app` — Git-клон приложения;
- `venv` — отдельное Python-окружение проекта;
- `data/clicker.db` — постоянная база, не входящая в Git и не меняющаяся при обновлениях;
- `.ssh/id_ed25519_github` — отдельный deploy key этого проекта для GitHub.

Перед первым запуском в Cloudflare у записи `A` для домена должен быть IP `65.20.72.135`. Для выпуска Let's Encrypt сертификата временно отключите проксирование (DNS only), либо убедитесь, что Cloudflare пропускает HTTP-проверку. После выпуска включите проксирование обратно и установите режим SSL/TLS **Full (strict)**.

Подключитесь к VPS под пользователем с `sudo`, скопируйте на него `deploy/bootstrap-vps.sh` и выполните:

```bash
sudo bash bootstrap-vps.sh
```

Команда напечатает публичный ключ. Добавьте его в GitHub в репозитории `MaxPeshCryp/cliker_v2`: **Settings → Deploy keys → Add deploy key**. Доступ на запись ключу не нужен. Затем на VPS:

```bash
sudo -u clicker git clone git@github.com:MaxPeshCryp/cliker_v2.git /var/www/clicker/app
sudo cp /var/www/clicker/app/.env.example /var/www/clicker/.env
sudo nano /var/www/clicker/.env
sudo openssl rand -hex 48
```

В `.env` вставьте сгенерированное значение вместо `replace-with-a-long-random-secret` и свой адрес вместо `replace-with-your-email@example.com`.

### Одноразовый перенос текущей базы

Когда директория проекта уже создана на VPS, но **до** первого запуска сайта, из PowerShell на компьютере выполните:

```powershell
.\\deploy\\push-initial-db.ps1 -SshUser root -IdentityFile C:\\path\\to\\your\\vps-key
```

Скрипт сначала убеждается, что `/var/www/clicker/data/clicker.db` отсутствует. Если база уже есть, он завершится ошибкой и ничего не перезапишет. Это защищает игровые данные при последующих релизах.

После успешного переноса базы завершите первый запуск на VPS:

```bash
sudo bash /var/www/clicker/app/deploy/update-vps.sh
```

### Следующие обновления

Базу больше не копируйте. На VPS после `git push` достаточно выполнить:

```bash
sudo bash /var/www/clicker/app/deploy/update-vps.sh
```

### Дополнительный домен max-click.iteacher-ai.org

Оба адреса открывают то же приложение с той же базой. Для нового домена
используется отдельный сертификат и Nginx-конфиг `clicker-ai`; прежний адрес
`max-click-pesh.iteacher-alex.org` продолжает работать. На новом домене потребуется
войти в аккаунт заново, поскольку браузер хранит cookies отдельно для каждого домена.

В Cloudflare в зоне `iteacher-ai.org` создайте запись `A`: имя `max-click`,
адрес `65.20.72.135`. На время выпуска выберите **DNS only**. Если есть запись
`AAAA`, она также должна вести на этот VPS с доступными портами 80 и 443;
уберите её, если IPv6 для сайта не настроен. TCP-порты 80 и 443 должны быть
разрешены в UFW и firewall провайдера.

После отправки файлов `deploy` в GitHub выполните на VPS от root:

```bash
sudo -u clicker git -C /var/www/clicker/app pull --ff-only
bash /var/www/clicker/app/deploy/enable-ai-domain.sh
curl -I https://max-click.iteacher-ai.org/
```

Скрипт читает email из существующего `/var/www/clicker/.env`, включает HTTP-проверку,
выпускает сертификат Let's Encrypt и затем включает HTTPS с перенаправлением
с HTTP. Если проверка домена не прошла, повторите команду после исправления DNS
или firewall. Приложение и база при этом не перезапускаются и не копируются.

После успешной проверки HTTPS можно вернуть **Proxied** и выбрать в Cloudflare
SSL/TLS **Full (strict)**. Не используйте Flexible. Существующий certbot timer
продлевает сертификат; deploy hook перезагружает Nginx после продления.
Проверьте расписание и тестовое продление:

```bash
systemctl list-timers --all | grep certbot
certbot renew --cert-name max-click.iteacher-ai.org --dry-run
```

Обычный `deploy/update-vps.sh` сохраняет дополнительный домен и обновляет его
конфигурацию, когда сертификат уже выпущен. Настройки остальных проектов не меняются.
