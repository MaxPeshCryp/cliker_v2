# Кликер

## Локальный запуск

Нужен Python 3.11+.

```powershell
py -3 -m venv C:\\Users\\$env:USERNAME\\clicker-venv
C:\\Users\\$env:USERNAME\\clicker-venv\\Scripts\\python.exe -m pip install -r requirements.txt
$env:CLICKER_SECRET_KEY = "вставьте-длинную-случайную-строку"
C:\\Users\\$env:USERNAME\\clicker-venv\\Scripts\\python.exe app.py
```

Откройте `http://127.0.0.1:5050`.

## Мини-игры на время

Доступны режимы «Спринт» (1 минута), «Тактика» (3 минуты), «Марафон» (5 минут).
На странице показаны компактные карточки. Кнопка «Играть» открывает забег в модальном
окне, «Рейтинг» — результаты выбранного режима. Окно можно закрыть крестиком,
клавишей Escape или нажатием на фон и снова открыть кнопкой «Вернуться».
Таймер при закрытии продолжает идти. При обновлении данных интерфейс меняет только
значения: карточки и кнопки сохраняются, рейтинг и история обновляются при изменении данных.
В каждой попытке отдельный нулевой баланс, клик +1 и нет роботов или бонусов основной игры.
Можно усиливать клик, покупать роботов и ускорять их доход. Результат — остаток монет
на счёте в момент финиша: покупки уменьшают результат. Перед игрой идёт отсчёт 3–2–1,
после которого доступны полные 1, 3 или 5 минут. До старта сервер запрещает клики
и покупки. Автодоход роботов сопровождается анимацией «+N» над счётом. Время, покупки и заработок
проверяет сервер; лимит — 10 кликов в секунду. Одновременно доступна одна попытка,
после финиша можно играть снова без ограничений. Закрытие или обновление страницы
не останавливает таймер. После возвращения показывается сохранённый результат.

У каждого режима свой рейтинг по лучшей завершённой попытке каждого игрока.
Он виден в игровом окне сразу: топ-3, затем место игрока и по одному соседу выше и ниже.
При равном результате выше рекорд, установленный раньше (при одновременном финише —
раньше начатая попытка). Все попытки хранятся в базе, последние 10 видны в интерфейсе.

Автодоход на основной баланс начисляется за время нахождения в тройке, включая время
вне сайта. Ставки в монетах в секунду:

| Режим | 1-е место | 2-е место | 3-е место |
| --- | ---: | ---: | ---: |
| 1 минута | 3 | 2 | 1 |
| 3 минуты | 9 | 6 | 3 |
| 5 минут | 15 | 10 | 5 |

Доход разных рейтингов суммируется, при потере призового места начисление прекращается.
Значения задаются в `timed_games.py`, `MODES`. Мини-игровые монеты не переводятся
на основной баланс. Призовой доход не даёт преимуществ в новых забегах.
При следующем API-запросе сервер завершает просроченные игры по времени их финиша
и рассчитывает смены ставок за прошедшее время; фоновый процесс не требуется.
Таблицы создаются автоматически при запуске, существующий прогресс сохраняется.
Старые рекорды один раз пересчитываются по сохранённым остаткам на счёте; история
попыток и уже начисленные награды сохраняются.

## Рекламные бонусы

Реклама открывается только по желанию игрока, по кнопке «Смотреть рекламу»:

- Под балансом: монеты раз в 5 минут. Награда — максимум из 100 монет,
  30 текущих кликов и 60 секунд текущего чистого дохода роботов.
- После мини-игры: однократно за последнюю завершённую попытку можно получить
  сумму её результата на основной баланс. Результат, рекорд и мини-игровой рейтинг
  не меняются. При нулевом результате бонус недоступен.
- Во вкладке «Бусты»: ×2 доход роботов на 60 секунд раз в 10 минут.
  Если турборежим уже работает, его срок продлевается на минуту.

В окне показано «Здесь могла быть ваша реклама». Через 5 секунд доступна кнопка
«Забрать бонус». Закрытие крестиком или Escape без получения ничего не начисляет.
Во время активного забега начать просмотр нельзя. Сервер фиксирует сумму при
открытии, проверяет время, владельца просмотра и защищает от повторного начисления,
в том числе после потери ответа или обновления страницы. Получить бонус можно
в течение 5 минут после открытия. Ограничения хранятся в базе.

Это демонстрационная заглушка без рекламной сети. Проверка времени сама по себе
не подтверждает просмотр настоящей рекламы; при подключении провайдера в
`rewarded_ads.py` нужна проверка его подтверждения просмотра на сервере.

Дополнительные возможные места: удвоение награды за возвращение в игру,
бонус при нехватке монет на улучшение, необязательный баннер под рейтингом.

## Инвестиции

Сумма вводится числом или с обозначением: `250M`, `2.5B`, `1,25 Qi`.
Поддерживаются K, M, B, T, Qa, Qi, Sx, Sp, Oc, No и Dc без учёта регистра.
Кнопка «Всё» подставляет точный баланс без округления отображаемого сокращения.
Срок каждого вклада — 30 секунд.

| Вид | Шанс успеха | Прибыль при успехе | Возврат при успехе |
| --- | ---: | ---: | ---: |
| Гарантированная | 100% | +20% | 120% вклада |
| Сбалансированная | 80% | +50% | 150% вклада |
| Рост | 60% | +100% | 200% вклада |
| Венчурная | 40% | +200% | 300% вклада |
| Джекпот | 20% | +500% | 600% вклада |

При неудаче вклад полностью теряется. Прибыль округляется вниз до целой монеты.
Шанс и сумма возврата фиксируются при создании вклада; получить выплату можно один раз.
Старые рискованные вклады сохраняют шанс 50% и возврат x2.

Для разработчика: `amounts.py` разбирает сумму через Decimal и выполняет целочисленные
расчёты. Значения вне диапазона SQLite INTEGER хранятся десятичными байтами (BLOB),
чтобы SQLite не преобразовывал их в неточный REAL. Функция `amount_add` сохраняет
точность списаний и начислений, рейтинг сравнивает целые числа в Python. Старые
числовые записи продолжают читаться. Поле API `userCountExact` содержит точный баланс
строкой; ввод суммы и денежные поля вкладов также передаются строками.

## Проверки

```powershell
C:\\Users\\$env:USERNAME\\clicker-venv\\Scripts\\python.exe -m unittest discover -s tests -v
```

Тесты используют временную базу и не изменяют рабочую `clicker.db`.

Для проверки интерфейса нужен Node.js, Playwright и Microsoft Edge. Запустите
`node tests/test_ui.cjs` и `node tests/test_timed_ui.cjs`. При необходимости задайте
`PLAYWRIGHT_MODULE` (путь к установленному модулю Playwright) и `PYTHON_EXE` (Python
с Flask). Проверка мини-игр сама запускает отдельный сервер с временной базой
и ускоренными часами, затем закрывает его. Она проверяет все три режима, покупки,
финиш, повторную игру, обновление страницы и мобильную ширину.

## Выгрузка на VPS

Production-конфигурация рассчитана на Ubuntu и домен `max-click-pesh.iteacher-alex.org`.
На сервере создаётся один изолированный каталог `/var/www/clicker`:

- `app` — Git-клон приложения;
- `venv` — отдельное Python-окружение проекта;
- `data/clicker.db` — постоянная база, не входящая в Git и не меняющаяся при обновлениях;
- `.ssh/id_ed25519_github` — отдельный deploy key этого проекта для GitHub.

Перед первым запуском в Cloudflare у записи `A` для домена должен быть IP `65.20.72.135`. Для выпуска Let's Encrypt сертификата временно отключите проксирование (DNS only), либо убедитесь, что Cloudflare пропускает HTTP-проверку. После выпуска включите проксирование обратно и установите режим SSL/TLS **Full (strict)**.

Подключитесь к VPS под пользователем с `sudo`, скопируйте на него `deploy/bootstrap-vps.sh` и выполните:

```bash
sudo bash bootstrap-vps.sh
```

Команда напечатает публичный ключ. Добавьте его в GitHub в репозитории `MaxPeshCryp/cliker_v2`: **Settings → Deploy keys → Add deploy key**. Доступ на запись ключу не нужен. Затем на VPS:

```bash
sudo -u clicker git clone git@github.com:MaxPeshCryp/cliker_v2.git /var/www/clicker/app
sudo cp /var/www/clicker/app/.env.example /var/www/clicker/.env
sudo nano /var/www/clicker/.env
sudo openssl rand -hex 48
```

В `.env` вставьте сгенерированное значение вместо `replace-with-a-long-random-secret` и свой адрес вместо `replace-with-your-email@example.com`.

### Одноразовый перенос текущей базы

Когда директория проекта уже создана на VPS, но **до** первого запуска сайта, из PowerShell на компьютере выполните:

```powershell
.\\deploy\\push-initial-db.ps1 -SshUser root -IdentityFile C:\\path\\to\\your\\vps-key
```

Скрипт сначала убеждается, что `/var/www/clicker/data/clicker.db` отсутствует. Если база уже есть, он завершится ошибкой и ничего не перезапишет. Это защищает игровые данные при последующих релизах.

После успешного переноса базы завершите первый запуск на VPS:

```bash
sudo bash /var/www/clicker/app/deploy/update-vps.sh
```

### Следующие обновления

Базу больше не копируйте. На VPS после `git push` достаточно выполнить:

```bash
sudo bash /var/www/clicker/app/deploy/update-vps.sh
```
